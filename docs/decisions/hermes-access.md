# Agent Note: Hermes 专用权限与不可重放的审批

Status: implemented

## Problem

把管理员密码或旧机器密钥交给助手，会让草稿整理变成无差别管理权限。网络重试、审批等待和进程中断也不能造成重复文章或覆盖人工修改。

## Decision

Go 进程使用官方 MCP Go SDK v1.8.0 的无会话 Streamable HTTP，凭据采用独立随机值，服务端只存 SHA256摘要。每个凭据绑定明确连接地址与权限，浏览器Origin另行校验；因此反向代理、Docker别名可用，未知Host不能通过。旧机器密钥不继承MCP权限。

默认只有公开查询、草稿读写以及公开／外观候选提交。私人笔记和Wiki单独授权；Wiki工具只复用已有规范文档只读入口，不运行模型。主题源码、删除、恢复、凭据管理和审批批准不作为MCP工具开放。服务账号、评论、统计和Meting接口地址仍由管理员维护。

后台和MCP复用内容Service、校验、配置revision、历史与发布队列。公开候选不改原记录；批准时核对内容revision，或同时核对配置值、配置revision和当前主题。恢复配置时版本号前进，防止旧页面或旧审批覆盖恢复结果。

request_id与规范化参数一起持久化。相同请求返回原记录，不再次写入；不同参数不能复用标识。应用意图先落盘，进程中断留下的applying标记为待核对，绝不自动重放。长时间等待和网络断开不等于回滚已保存数据。

新增助手写入只允许Markdown，不允许原始HTML或脚本；代码块中的HTML示例保留。原管理员与旧REST API合同不变。差异预览只显示转义文本，不执行候选内容。凭据、审批和记录不进入公开快照或数据备份。

## Alternatives considered

- 复用管理员Session或旧机器密钥：权限不可分，拒绝。
- 助手修改后才通知管理员：公开前无法审批，拒绝。
- 重新执行中断写请求：无法区分保存前后，可能重复创建，拒绝；改为持久状态和人工核对。
- 自行实现JSON-RPC传输：协议演进与安全边界维护成本高，采用官方SDK。源码构建最低Go版本相应提升到1.25，Docker使用Go1.26无需用户单独安装。

## Consequences

日常草稿可直接维护，公开修改必须批准并查询实际上线状态。MCP本身不发起模型调用；Hermes自身的模型使用由其配置决定。连接检查只检查本应用的凭据和协议，不能代替Hermes宿主机的网络检查。主题0.2需要后台接口兼容级别2，旧主题1级仍可使用；独立维护入口保留审批和撤销，回退主题也不会失去这两项控制。
