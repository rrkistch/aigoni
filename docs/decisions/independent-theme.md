# Agent Note: 主题来源与公开版本一起切换

Status: implemented

## Problem

将主题与后端打进同一镜像，让装修和代码升级耦合。若先修改当前主题指针、再构建页面，失败或中断会导致主题配置和公开页面不一致。

## Decision

主题通过固定仓库 GitHub 正式 Release 的资产大小和 SHA256验证。包清单提供格式、平台、Node、pnpm与配置接口版本；不能自行声明受信任来源。解压不执行脚本，拒绝特殊文件与越界路径，仅容许依赖目录内可解析的相对符号链接。

安装版本与可写工作副本分开。公开快照固定主题标识、内容和覆盖设置。只有成功构建且仍为最新 revision 时，才在原有 site-build 状态文件中同时切换页面和主题；失败不切换。回退重新构建当前数据，配置能力不兼容就阻止操作。

## Alternatives considered

- 接受包内自报来源或浏览器提供校验URL：可伪造，不采用。
- 解压后直接在安装目录构建：污染可回退版本，不采用。
- 两份文件分别切换主题和页面指针：中断会产生混合状态，不采用。
- 直接恢复旧页面：可能恢复撤回内容，不采用。

## Consequences

主题上传不需要重建后端镜像；纯前端修改不触发镜像发布。首次安装需要可访问GitHub，并为安装版与工作副本预留磁盘。过渡镜像保留源码，独立包验收后才剥离；当前阶段不将这一过渡状态描述为拆分完成。
