# Agent Note: 数据恢复替换与中断回滚

Status: implemented

## Problem

逐个文件覆盖会混合新旧数据，进程中断可能留下半份内容。恢复旧的公开构建还可能重新暴露已撤回文章。

## Decision

备份只打包允许的数据分区，不复制整个数据卷。恢复先解压校验，在确认时检查校验后数据是否变化；阻止写入和读取，创建恢复前安全备份，再用持久化事务日志逐个替换分区。中断恢复首先回滚至一致状态。公开版本在替换前停供，恢复后以当前数据重新构建，不恢复旧静态页面。

独立维护入口不依赖主题资源；凭据与会话不属于备份分区。恢复保留部署路径，因此可迁移到不同目录，不接受包内指定的任意落盘路径。

## Alternatives considered

- 整个数据卷直接打包：包含密钥、会话和可重建依赖，不采用。
- 解压覆盖已有目录：无法表达删除和空分区，产生混合版本，不采用。
- 还原旧静态页面：有重新公开撤回数据的风险，不采用。

## Consequences

恢复需要暂存空间和安全备份空间；站点会短暂进入维护状态。外部直接写文件的脚本不受应用锁控制，管理员需先暂停。任务状态读写共用短临界区，避免 Windows 轮询读取时阻止原子替换；中间状态写入失败会中止操作而不是继续恢复。有效证据包括归档边界测试、事务中断回滚，以及带 Session 的实际备份上传、校验、恢复和冲突流程。
