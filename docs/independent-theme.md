# 独立主题包：安装、升级与回退

## 什么时候需要更新

写文章、换头像和壁纸、修改配色、导航、音乐与模块内容，只在后台保存即可；不需要升级主题或后端镜像。

主题代码变化才上传主题包。后端或 Node 运行环境变化才更新后端镜像。主题使用独立的 `theme-v主版本.次版本.修订号` 标签；后端稳定镜像使用 `container-v...` 标签。

## 首次安装或主题升级

1. 先在“网站维护”创建并下载数据备份；密钥需另行保管。
2. 更新到包含“主题更新”的后端版本，保留原数据卷和主机18080端口。
3. 登录后台“主题更新”。若主题无法打开，访问“你的后台路径/maintenance”；例如后台为 `/studio` 时使用 `/studio/maintenance`。
4. 在本项目 GitHub Releases 下载 `aigoni-theme-v版本-linux-amd64.tar.gz`，保持原文件名。首版只支持 Linux amd64、Node24和pnpm11.22.0。
5. 上传文件。断线后重新选择同一文件续传；验证中可取消。服务器会通过固定仓库的正式发布信息取得 SHA256，核对大小、文件、兼容版本与解压边界。服务器无法访问 GitHub 时，检查网络后重试，不能跳过来源验证。
6. 状态为“验证通过，可启用”后，点击“构建并启用此主题”。等待当前版本变为目标主题并确认“已上线”。上传或保存成功不等于上线。

文件最大1GiB，解压最多4GiB；还需可写构建副本、生成页面及128MiB以上余量。内存限制与磁盘空间不是同一个指标。服务器不执行依赖安装命令，包内已经包含锁定版本依赖。

当前过渡镜像仍带原源码，以保证迁移入口；成功验证独立主题发布和限额容器流程后才移除。不要因为主题后台已出现就删除数据卷或旧镜像。

## 回退

在“主题更新”点击“用上一主题重建当前网站”。回退使用当前文章和设置，绝不直接恢复旧静态站点；因此不会重新公开已撤回文章。

普通构建失败继续提供上一成功版本。候选主题不兼容现有设置时阻止启用，并保留设置；不自动删除用户配置。首次独立安装之前的“原源码目录”只有在该目录仍可用时才能重新构建。

## 数据与运行目录

- `.aigoni-admin/themes/versions`：已验证安装版本，不在此执行构建。
- `.aigoni-admin/themes/work`：可写构建副本，依赖只复制一次。
- `.firefly/releases`：成功生成的公开页面。
- `.firefly/state.json`：公开版本与当前/上一主题在同一个原子状态中切换。

这些目录不作为任意静态目录暴露。保留当前、上一与待用候选主题，清理无引用版本；未完成上传闲置24小时后定期清理。数据备份记录主题版本，但不复制主题依赖，换机器时需重新安装对应主题包。

原生源码目录模式和原前端恢复方式保持可用。不要把私人资料放进主题源码；公开构建快照只包含明确公开字段。
